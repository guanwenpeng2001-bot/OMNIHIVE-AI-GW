# Platform model information

Public documentation checked **2026-10-03 Asia/Shanghai** (captures dated October 2 UTC). Model IDs, limits, lifecycle, and methods are specific to the provider, product, host, region, and exact ID. A candidate is a suggestion for account configuration; the account's discovered inventory and saved selections determine access. Public listings do not establish permission, subscription eligibility, quota, or a successful inference call.

The complete machine-readable inventory is [`preset-sources.json`](../backend/resources/model-capabilities/scripts/preset-sources.json), reproduced in [`platform_model_presets.json`](../backend/internal/service/platform_model_presets.json). Both retain historical IDs when current public availability is unverified. An ID missing from a new index is not marked retired without an official retirement statement.

“Fill Presets” excludes only models explicitly marked `retired`. Deprecated models, future retirement notices, previews, and unknown lifecycle states remain candidates. Historical preset metadata and already selected, mapped, or discovered account models remain intact.

## Hosted and protocol boundaries

Vertex Gemini and Vertex Anthropic are hosted profiles of existing platforms, not new platforms. Only exact publisher IDs supported by first-party hosted evidence can become candidates. Project, location, enabled APIs, and account entitlement remain independent requirements. Gemini API facts cannot serve as fallback evidence for Vertex.

This inventory includes **24 Vertex Gemini candidates** under `vertex-gemini`, each with its own Google Cloud source. No Vertex Anthropic preset is added: complete versioned publisher-ID evidence remains a gap. For example, [Vertex Gemini 3.8 Flash](https://cloud.google.com/vertex-ai/generative-ai/docs/models/gemini/3-8-flash) independently documents its limits; Vertex Live's abbreviated `128K`/`64K` is not replaced by Gemini API integers. API and hosted shutdown schedules also differ: `gemini-2.5-flash-image` shut down on the Gemini API on October 2, 2026, while its [Vertex schedule](https://cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versions) gives March 15, 2027.

Recent API additions include Anthropic `claude-opus-5-5` and `claude-sonnet-5-5`; OpenAI `gpt-6-luna`, `gpt-6-sol`, and `gpt-6.1-sol`; Gemini `gemini-3.8-live`, `gemini-3.8-live-extended-thinking`, the two 3.8 Flash TTS IDs, `gemini-3.5-transcribe`, and `lyria-3.5`; xAI `grok-4.7`; and the exact Mistral model-card IDs `codestral-2508`, `mistral-medium-3-5`, `ministral-3b-2512`, `ministral-8b-2512`, `ministral-14b-2512`, `mistral-ocr-4-1`, `mistral-moderation-2603`, and `voxtral-small-2507`. The source projection also retains independently listed snapshot IDs with unknown capabilities when their individual limits are not documented.

For Anthropic, Opus 5.5 defaults to medium effort and Sonnet 5.5 to high. The advertised 300K Batch beta output is separate from synchronous Messages. For OpenAI, [6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) does not support Chat Completions tool calling, and [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) permits Chat tools only with `none` reasoning. Codex subscription retirement announcements do not retire the public API IDs. For [Grok 4.7](https://docs.x.ai/developers/grok-4-7), the official description of no text output limit is not encoded as zero or an invented maximum.

New Bedrock candidates use exact AWS model-card IDs. Some cards distinguish bare model IDs for the Mantle endpoint from regional/global inference-profile IDs for Bedrock Runtime; this inventory does not construct prefixes or add account inference profiles. An AWS model card does not establish that a particular gateway action supports Mantle, media, or embedding invocation.

Kimi Code publishes CN/global OpenAI-compatible bases (`api.kimi.com/coding/v1`, `api.kimi.ai/coding/v1`) and Anthropic-compatible bases (`/coding/`). [Responses support](https://www.kimi.com/code/docs/third-party-tools/codex.html) accepts text and images, not video; a model's overall input modalities therefore do not imply the same modalities on every method.

Alibaba's coding bases use `coding.dashscope.aliyuncs.com` and `coding-intl.dashscope.aliyuncs.com`; those credentials and model lists are separate from PAYG. MiniMax distinguishes subscription keys from PAYG on shared API hosts. GLM plan routing behavior must not be applied to the PAYG profiles. Documented compatibility describes upstream metadata and does not change the gateway's supported actions or routes.

Baidu personal Token Plan and Tencent Coding/Token Plan documentation describe interactive compatible-tool usage conditions, including restrictions on scripts/custom backends; Tencent also describes sharing restrictions. These are dated product terms for the corresponding plan, not model capability fields. Explicit account base URLs and saved mappings remain authoritative configuration.

## Reading freshness and missing fields

`field_sources` identifies the source URL for each fact. A profile's `coverage_scope.official_review.records` binds a reviewed exact ID and field to the corresponding source ID, capture hash, observation time, and disposition. Model-level `verified_at` and `source_content_hash` remain the earlier observation for records that still contain inherited facts; they do not certify newer sibling fields. New source captures have new IDs and never overwrite historical hashes.

All inventories remain partial except OpenRouter's explicitly unconfigured list. Unknown methods are empty, unknown reasoning is omitted or marked unknown, and unknown numeric fields are omitted. Total context, maximum input, and maximum output are independent claims; a `K` or `M` abbreviation alone does not select a decimal or binary multiplier. No prices, account selections, model mappings, or discovery permissions follow from this reference.
