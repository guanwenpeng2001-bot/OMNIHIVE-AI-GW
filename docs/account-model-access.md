# 账号、分组与 Key 模型访问合同

本文说明账号、分组、Key 与具名集合的访问规则。相关模型元数据约束见[模型注册表合同](model-registry-contract.md)。

## 身份、路由分组与具名集合

| 对象 | 责任 | 必须保持的边界 |
| --- | --- | --- |
| workspace | 账号、分组、渠道、代理、监控、Key 和 secret 的资源作用域 | 所有列表/详情/统计/批量/导入导出/任务必须检查作用域，不能只给查询列表加过滤 |
| 账号 | 某凭据拥有者在当前协议、托管画像、端点、region/project 和 revision 下的上游身份 | 换凭据/端点/头/代理/secret 等必须失效旧证据；同名模型不跨身份授予权限 |
| 路由分组 | 账号有效公开模型的并集及分组规则/配额/暴露控制 | 没有可路由绑定的预设不能变成可用模型；Bedrock 子类型限制不能因归入 Anthropic 被扩大 |
| Composite | 已配置的有序目标及公开名映射 | 只在授权内、同公开语义、动作/参数兼容的目标间切换，不能静默换另一个模型或密钥 |
| Key | 业务调用主体，绑定原有 owner/group 与预算/状态/策略 | Key ID 在凭据轮换后不变，所有协议与任务仍用同一授权链 |
| 具名模型访问组 | 可复用的模型集合定义，具有稳定 ID、名称、既有规则模式、成员/规则和 revision | 它不是路由分组，不创建账号绑定，不授予 workspace 或供应商权限；账号/Key 可按 ID 引用 |

默认 workspace 必须幂等回填，成员与工作区管理员为所需角色；委派入口使用 `/api/v1/workspaces/:workspace_id/...`，复用服务并显式传 scope。全局 admin 守卫必须保留，不得为委派整体放宽，也不新增未要求的只读角色体系。

### Composite 路由与会话亲和性

Composite 必须使用显式有序目标集合，并共同调用现有 Claude/OpenAI 两主干及既有调度设施，不得新增独立路由流水线。region/provider 限定、延迟偏好和 `scheduling_weight` 必须作为独立字段语义表达：region/provider 限定必须裁剪可选目标，延迟偏好和权重只能在满足授权、动作及限定条件的候选内影响选择，不得绕过限制。`concurrency` 必须继续作为硬并发控制，调整权重不得改变并发上限。

未显式配置新策略时必须保持旧账号权重和路由行为，旧 `load_factor` 等值必须等效兼容，不能因默认回填而改变分流。显式 session/user 信号必须优先于 legacy IP/UA，IP/UA 仅作旧行为兼容；会话键必须复用既有 affinity 范围与 HMAC 设施，不得跨 Key/组/模型串会话。affinity TTL 必须可配置，未配置时必须保持旧默认。

验收必须证明 region/provider 限定不被延迟偏好或权重绕过、调权不改变硬并发、未配置新策略的旧账号路由及权重等效；同 IP/UA 下不同显式会话必须按显式信号区分，跨 Key/组/模型不得复用亲和结果，TTL 的旧默认与显式到期必须分别生效。

## 有效集合的求值顺序

1. 先取得当前账号身份的发现/声明/探测证据；仅候选预设不算证据。发现记录必须绑定 identity/rules/snapshot revision。
2. 将证据与真实动作实现、账号规则求交，得到账号 Eligible；模型能力未知不能伪装成 false，但缺适配器不等于支持。
3. 将组内 Eligible 投影为可路由公开名后取并集，再执行分组规则与 Composite 显式目标/映射约束。
4. Key 未设置策略时继承此分组有效集；已设置策略时与其求交，结果只能变小。具名集合及 include/exclude 在所属账号或 Key 层求值，仍受上层约束。
5. 按请求公开名授权，再映射到真实上游绑定，并在发送前重新校验身份、动作、参数要求及权限；每次重试/换路都必须重验。

同一 Key 的极简列表、富目录、单模型、模型广场、可用渠道、监控公共投影和真实调用必须使用同一 resolver/revision。不得在某页暴露另一页已禁止的模型；单查不可见与不存在统一 404。任务的创建、查询、取消、下载、文件/批量资源同样必须检查 owner Key/workspace 及当前允许操作的范围，不能拿上游 task_id/file_id 猜所有权。

### 未设置、显式空与兼容语义

| 输入或持久状态 | 必须解释为 | 禁止的误解 |
| --- | --- | --- |
| Key 策略未设置或 null | 继承分组当前有效集；必须保留“未设置”这一状态 | 序列化为 `[]` 后当显式拒绝，或按平台全预设继承 |
| Key 明确设置空集合 `[]` | 有策略且有效集合为空，即不允许任何模型 | 把空数组改成 null/继承，或因长度为零自动放开 |
| Key 明确非空策略 | 与组有效集合取交集 | include、别名或通配超越组权限 |
| 账号旧空数组 | 保持原账号模式的既有空规则语义，未限制时只是不追加限制；仍受当前身份证据与动作约束 | 套用 Key 新语义变成全拒绝，或提升为全预设有授权 |
| 既有账号透传/通配规则 | 保留原模式；有限已知集可枚举，未知名称按实际请求和权限链求值 | 无限展开候选目录或用旧残留 mapping 覆盖显式透传模式 |
| 更新请求省略某策略字段 | 不修改该字段的已存状态 | 省略即清空、解除引用或复活过期/耗尽/人工停用 Key |
| Key 关联字段更新省略 / 明确 0 | 省略不变，0 解绑；用户/管理员入口一致，旧 null 由兼容适配解释 | 查询 ID=0 或把省略当解绑；此规则不改变模型策略 null 的继承语义 |

迁移必须保留 null 与显式空，不能统一回填为空数组。账号兼容模式与 Key 新策略必须用不同语义解释，不能只按 `len(models)==0` 决定授权。

## 具名集合引用与少量覆盖

引用合同为稳定 `model_access_group_id` 加 `include`、`exclude` 少量公开模型名覆盖；持久表示可复用既有字段/extra/revision，由所属 schema 任务落实，但必须能区分引用、未设置和显式空。名称用于展示，ID 用于引用，重命名不得断开关系；引用和目标必须同 workspace，任何入口不得只信前端传入 ID。

具名集合先按既有模式计算基础集合，再执行“加 include、减 exclude”，exclude 对同名冲突优先；最后必须再次与所属账号证据/动作边界或 Key 的组有效集合求交。include 只能扩大该具名集合在上层许可范围内的选择，不能扩大父范围。不能通过包含内部部署名、隐藏 canonical 或跨域集合取得额外权限，不引入条件脚本或任意 DSL。

例如分组有效公开名为 `chat-public`、`embed-public`，具名集合只有 `chat-public`：Key 引用该集合并 include `embed-public` 可以得到两项；include `private-deployment` 不会获得绑定或额外权限；exclude `chat-public` 后只能保留 `embed-public`。显式空 Key 策略仍是空集，不会因为组后来新增模型自动变成继承。

所有规则必须作用在请求公开名上。别名 `chat-public` 映射到真实模型时，先判断 `chat-public` 是否获准，再检查真实目标绑定；允许 canonical 不应隐式放行一个被排除的公开别名。公开 aliases/canonical 仅包含当前域内可绑定名称，不能把内部部署 ID 当别名输出。

## 引用删除、修改与立即失效

具名集合删除必须在事务中检查引用：有引用时必须先显式解除/迁移引用，或返回可解释冲突（409）；不得静默变成继承、扩大权限或留下悬空外键。解除引用与被引用集合删除的并发必须受事务约束，不能“先查再删”产生竞态。界面必须展示受影响的账号/Key，且只暴露操作者域内资源。

集合内容、include/exclude、Key/组/Composite 规则、workspace 归属或绑定变化必须推进相应持久 revision/generation，随业务事务写 outbox；删除保留旧归属，搬组记录旧新组。本机提交后失效，各实例通过通知和权威版本核对保证立即生效。目录/鉴权缓存命中前必须校验当前版本，通知丢失或断线不能继续公开旧集；校验失败回源仍失败就报错，不能用 TTL 等撤权自然过期。

后续分页必须重新校验当前权限，旧游标不能还原撤销授权。在途已提交请求仍按冻结 plan 记录已发生用量；撤权不删除收据、不制造免费，不以旧 plan 给新请求或后续分页恢复权限。异步任务按持久 owner、版本、绑定和当前作用域校验读写，终态不因迟到更新退回失败。

## Key 凭据轮换与权限一致性

同一个 `api_keys.id` 使用从属凭据记录和摘要查找，最多当前凭据加上一凭据双活；默认宽限 24 小时且可配，第二次轮换必须终止更旧宽限。新 secret 只在创建/轮换响应展示一次，常规列表/详情/管理员页面只显示掩码或独立后缀，不能回读 secret。

两份凭据共享 Key 的组、模型策略、workspace、预算、用量和审计归属。鉴权缓存必须同时考虑凭据期限/撤销及 Key policy/workspace revision，逐请求校验有效期，后台清理不能延长宽限。管理员停用/删除/轮换必须有所有权/作用域和审计，触发既有 Key 处置不能因 owner 是全局管理员而忽略，也不能封禁其整个管理会话。

摘要迁移必须按“全实例兼容凭据表与双读 → 回填摘要并验证存量鉴权 → 停止明文回读/写入 → 分批清除旧明文”完成；不能用原明文列塞假 secret，不创建第二把业务 Key，不从备份恢复已撤销凭据。清除后最低回滚版本必须理解摘要认证，详见配套注册表合同。

## 预算周期、预留与结算冻结

预算必须复用既有 receipt、余额冻结和原子结算，不新增第二账本。USD 成本窗口、模型权限、RPM、TPM、并发和路由权重分别表达，不能用“限流”混称所有状态。

| 周期/状态 | 必须行为 |
| --- | --- |
| 固定日/周/月 | 明确 IANA 时区及实际边界，覆盖月末和 DST；周起点/锚点必须明确展示与计算一致，不隐含随服务器时区改变 |
| 自定义时长周期 | 使用一个明确 duration 与 anchor 的周期模式，必须能重算 period 标识/起止，不建设任意预算 DSL |
| 旧 5h/1d/7d | 保留既有窗口/锚点语义并准确展示，不偷换成固定日历周期或清空已消费 |
| 请求准入 | 原子预留预算/余额，唯一 Key+period+request 身份关联 receipt，跨实例并发不能无条件透支 |
| 结算冻结 | 准入时冻结 policy revision、period、报价及结算身份；延迟结算仍归原 period，跨月/改时区/轮换不挪到新周期 |
| 最终修正 | 按实际已取得 usage/成本证据原子实扣、释放或调整；未知上游消耗保留待结算状态，进程崩溃可补结算/回收，不伪造零消耗 |
| 用户编辑 | 自设上限可以编辑，不能清平台强制预算或已结算消费；改策略不归零，轮换/解绑不清历史 |
| 管理员调整 | 通过已有审计化调整/补偿记录处理，保留原账务事实，不直接抹已消费数或整库还原 |

请求取消和总 deadline 必须继续传到上游，但不能承诺供应商不收费；收据记录已观察用量与 interrupted，独立短尾必须仅持久化已取得计费证据，不得继续生成。换路必须同时明确未提交副作用且未输出语义内容，心跳本身不能证明双前提成立；首语义输出后不得跨上游重放，幂等重试不能再次起生成/收费。计费失败与 panic 恢复必须复用现有 receipt/outbox，禁止 nil settlement 分叉，完整验收及无通用供应商 resume 边界见[请求生命周期与恢复边界](model-registry-contract.md#请求生命周期与恢复边界)。Composite 换目标只允许同公开语义、动作兼容、授权范围内的显式目标，重新冻结目标成本报价时保留用户已承诺销售价和同一结算身份。

限额拒绝必须解释真实来源。OpenAI 余额不足为 429/insufficient_quota，Anthropic 为 invalid_request_error，Google 为 RESOURCE_EXHAUSTED；权限不足另用各协议权限错误。硬余额不足不伪造短时 Retry-After，窗口/队列/上游有恢复依据时才输出相应真实信息，不能泄露账号总额。预算耗尽、过期、人工禁用必须分别展示，编辑不能悄悄复活 Key；`/v1/usage` 可查询被限 Key，但 isValid 必须反映实际可调用状态并含真实 expires_at。

## 验收场景与迁移下界

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同组两账号分别有不同有效模型 | 组取并集；加入无资格候选不得增加公共目录；Key 限定后列表和调用同时缩小 |
| 未设置、显式空、有限 Key 策略 | 三种状态往返保存不混淆；所有协议、广场和渠道一致，空集不硬塞默认 gpt/grok/Claude |
| include/exclude 与别名 | include 不超组，exclude 冲突优先；公开别名先授权再映射；不能用隐藏目标绕过 |
| 具名集合修改/删除与双实例 | 修改提交即失效，丢通知仍有版本校验；被引用删除冲突，事务竞态不悬空，不回退继承 |
| 跨 workspace 与任务资源 | 列表/详情/统计/导入导出/批量/任务/文件均拒绝越权，资源不存在与无权不可被差异探测 |
| 轮换、二次轮换、到期/撤销 | 两凭据共用一个 Key/账单，旧宽限逐次校验，二次轮换结束更旧凭据；无 secret 常规回读 |
| 月末、DST、改策略与延迟结算 | period 可复算，已冻结结算仍入原周期；旧窗口不变，已消费不清，轮换不重置 |
| 并发、取消、崩溃和重复结算 | 原子预留/修正，receipt 幂等恢复；保留实际消耗，不重复扣款、不把未知当免费 |

访问组迁移必须加法引入集合、引用、revision 并保留 null/显式空；有规则数据存在后不得回滚到忽略规则的版本。workspace 有新域数据后不得回滚到不执行 scope 的版本；预算错账使用补偿记录，不回滚覆盖新账本。
