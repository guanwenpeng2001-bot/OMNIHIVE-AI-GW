# OmniHive v0.3.5：作用域、目录、价格与运营一致性交付方案

状态：执行基线；实现与验证状态另记于同目录交付报告，本文不代表测试已经通过。

基线：`94d8a70b39c46895cac3817f3b230fb5eabe2692`，对应 `main` 和 `v0.3.3`。用户明确指定本次目标版本 **v0.3.5**，授权完成方案、相邻问题排查、实现、测试和 GitHub PR。发布 tag、合并及生产部署不属于提交 PR 的动作。

## 1. 执行摘要与发布边界

目标是让同一模型、同一主体、同一凭证、同一请求在列表、详情、报价、执行和账单中得到一致且可解释的结论。统一事实和求值器，保留协议、视角、管理职责及财务类别的合法差异。

本次必须交付：

1. 个人空间始终可达；新用户保持 Default 工作空间成员身份和零 project_grants，通过个人 Key 自助调用。零余额时提示资金问题，不产生项目权限错误。
2. Scope 只有一个写入者；项目 Key、逐项目授权、Playground、Key 生命周期、报价确认和错误状态形成闭环。
3. WorkBuddy 模型规则保存、关闭、重开、刷新往返一致，并检查相同初始化分支涉及的 Gemini/Anthropic OAuth 等平台。
4. 目录字段有真实来源；公开发布、发现、候选、路由、调用权限、销售价格独立表达。参考价不能进入预算或实收。
5. 去除有歧义的价格猜测，统一目录/报价/执行所需的价格上下文，保留已冻结请求与历史账单算法。
6. 修复配置读取故障降级、密文错误当明文、失效缓存等邻接问题；统一关键默认值、来源诊断和显式恢复继承。
7. 版本、发布清单、迁移与回滚约束一致；提交带证据和剩余环境限制的 PR。

原先的 v0.3.4 热修边界保留为本 PR 内可独立审查的提交组，不再创建另一个计划版本。v0.3.5 采用加法合同、兼容适配和前向迁移。不可证明兼容的删除、全量重写、历史账单重算不进入本次。生产启用新写入权威必须通过迁移和回滚门禁，不能以版本号相同代替兼容证明。

成功标准：安全反例零放宽、provider 串用零容忍、未解释收费差异为零；已保存配置不因 UI 初始化或 GET→PUT 丢失；所有页面的允许/拒绝/未知状态与服务端一致；验证报告明确区分已通过、失败和受环境阻断。

## 2. 一概念一事实源

以下为逻辑实体，不要求机械新建同名表；应优先复用现有实现。

| 实体 | 权威与写入边界 | 版本与冻结规则 |
| --- | --- | --- |
| ModelIdentity | provider 命名空间 + 上游原生模型标识；目录唯一解析器 | 登记既有 `m_` ID，不改变现有 hash 生成语义；canonical/alias 合并保留旧 ID 映射 |
| ModelAlias | 已批准的、带 provider/协议/作用域限定的绑定 | 请求接纳时冻结解析结果与绑定版本；禁止模糊命中自动提权或串价 |
| CatalogEntry | 现有 ModelRegistrySnapshot 信任链与统一目录读模型 | 目录修订不可变；active 指针原子切换；所有入口使用投影适配器 |
| Provenance | 每字段的来源断言及审阅决策 | origin、approval、visibility 分离；pi 经批准后 origin 仍是 pi |
| DiscoveryObservation | 账号/连接发现记录 | 保存身份版本、观察时间、有效期；不覆盖运营选择、不自动启用 |
| Publication | 运营发布动作 | draft/published/withdrawn；不由发现、路由或价格推导 |
| Connection / Offering | 连接应用服务；账号为兼容调度投影 | 单一命令写者；旧接口委托新命令，禁止长期双向双写 |
| PriceBook / TariffVersion | 现有 exact_price_versions、统一销售解析器和版本化激活绑定 | 费率内容不可变；生效区间由唯一有审计绑定管理；发布原子终止旧绑定、激活新绑定 |
| PriceQuote | 统一 PriceContext 经授权后生成 | 冻结模型、scope、Key、payer、价格/策略版本、公式、计量单位、币种、时间锚点、请求指纹 |
| RequestPlan / UsageReceipt | 现有请求计划、预算预占及计费快照 | 复用 PricingAt、父分组、幂等与历史 rounding 语义，不另建收费链 |
| Scope | 后端 Identity 求值；前端 app store 的作用域子状态唯一持有 | personal/workspace/project 区分；选择与权限分离；保存 schema/user 版本 |
| Grant | 现有 project_grants 成对记录 | 按项目+action 读写，成员授权版本 CAS；旧有损矩阵不得扩权 |
| KeyPolicy | 一个有效策略解析器；现有两套表迁为单向兼容投影 | action/model/IP/预算等按各自合同求交集；空、缺失、无限制不能混用 |
| SettingEffectiveValue | SettingRegistry + 现有设置应用服务 | 显式 override；set/reset 分开；配置版本、应用版本和来源可诊断 |
| ReleaseCompatibility | 现有 release manifest 的单一生成输入 | tag/commit/digest/schema floor/semantic floor 一致；稳定资产不可覆盖 |

必须保留的差异：模型原作者与 API 提供方；公开事实与作用域可用性；模型规格与连接能力；别名与重写规则；工作空间管理权与明确生效的项目使用权；个人逻辑归属与 legacy Default 物理账务映射；销售价、参考价、内部成本、结算记录；真实零价与缺价；普通用户并发与安装管理员并发；协议适配与事实求值。

源码核对后的兼容约束：Workspace admin 当前继承全部非 platform actions，本次不暗改这个角色；授权页展示 inherited/effective。LegacyScope 的个人 Key 默认项目映射保留在兼容层，不能删除该例外或重写历史归集。现有撤权、keys.act_as、payer、原始事件读取、一次性 secret 和预算检查必须保留。

## 3. 统一目录、价格和广场

### 3.1 字段来源与合并

不使用一条全局来源排序决定所有字段。

| 字段 | 规则 |
| --- | --- |
| 身份与 alias | 明确批准绑定；发现只提出候选；歧义返回原因，不猜 provider |
| 标题/描述/标签 | 显式运营覆盖 > 已审阅内置 > 平台资料 > pi；覆盖有审计 |
| 通用能力 | 已批准事实优先；参考仅补 unknown，不覆盖明确 false；保留 suppressed_fields |
| 连接支持能力 | 当前连接配置、适配器约束、观察证据共同求值；不升级成全局保证 |
| 权限 | Identity + KeyPolicy；目录数据永不授予权限 |
| 销售价 | group > channel > 已登记 legacy sale fallback；来源在导入/合并字段时保留 |
| 参考价 | 独立 reference_prices；与销售解析无优先级关系 |
| 发布与健康 | 各自权威事件/观察；过期证据变 unknown |

Provenance 至少包含 source_kind、source_id/revision、field_path、observed_at、approval、selected_reason；管理端保留完整证据，公开端仅显示脱敏来源。producer、projector、publisher 的 source 校验必须同批更新，保留公开字段白名单，不能仅换 UI 标签。

### 3.2 状态合同

三组状态与独立发布字段：

* 来源：origins[]；curation=candidate/approved/rejected；discovery=not_observed/observed/stale。
* 可用性：unknown/requires_scope/unavailable/eligible/live，附 evaluated_scope、reason、observed_at。eligible 表示存在合规候选，live 还需要新鲜健康证据。
* 计费：priced/scope_required/multiple_offers/missing/partial_rate/conflict/conditional。conditional 是完整分段公式时仍可报价；缺维度才阻断。
* 发布：draft/published/withdrawn，不从上述三组推导。

不同分组不同售价是合法 multiple_offers；只有同一完整计费上下文同优先级规则重叠才是 conflict。支持 live+missing、live+partial_rate、live+conflict；路由可用不表示能够完成付费执行。字段缺失为 unknown，禁止前端从 price/route 猜 availability。

public 是 audience，personal/workspace/project 是 scope_kind；不能继续用 project_id=0 代表 public。公开页不显示针对当前用户的“Live & Routable”；候选资料不暗示承诺接入。无销售价时主列显示“暂无销售报价”，参考价独立弱化展示来源与日期。

### 3.3 身份与销售价格

provider 是实际 API 命名空间，不是底座模型作者。101 个跨 provider 同名情形必须按 provider+原生标识隔离；group pricing 已有 platform 过滤要保留。新解析禁止 lastSegment/去后缀多匹配取首项；排序后取首项也不是语义解决方案。已批准兼容映射和已生效销售 fallback 不因名称修正被擅自撤销。

四类价格严格分开：ReferencePrice 不产生可执行版本；SaleTariff 用于报价/预算/实收；CostBook 仅内部可见；Settlement 保存发生时事实，不查今天目录重算。BYOK 仍有项目权限和明确的服务收费合同；不得把参考价或缺价当免费。

报价接纳 TTL 默认 60 秒；接纳后长流式请求使用冻结费率/公式，不因 TTL 到期重定价。使用实际 usage 代入冻结公式；重试/重放按原请求幂等结算。跨 provider failover 必须满足原授权及冻结售价约束；不能执行后涨价。分时使用保存的时区，新规则默认 UTC；旧规则保留原时区。新重叠时间规则默认拒绝，明确叠乘须显式声明。历史复合、分阶段舍入票据保留原引擎版本。

### 3.4 API、存储、缓存和快照

复用 `/api/v2/public/models` 作为公开标准读模型，项目视图使用相同基础 schema 和独立 scope 评价。`/v1/models`、`/v1/models/catalog`、legacy plaza、channels/available 保留协议合同，由适配器读取统一事实；不把全部参考候选注入原本可调用模型列表。

现有 `catalog_version` 用于同一列表到详情的稳定读取。当前配置+历史指标窗口不得冒充历史配置快照；真正历史读取必须绑定不可变 revision。内容版本、active 指针、发布租约分离；相同内容刷新应续租，不改事实。发布副作用逐步从 GET 隔离，发布失败不得破坏已验证快照。

Redis 仅作缓存。复用现有 scope/generation/registry/runtime mapping 失效边界，补 policy/price 版本；缓存 key 包含 audience、tenant、scope、KeyPolicy 和价格上下文。目录 TTL 不能承担撤权。请求链不能现场访问 pi/外部目录网络。

管理员“模型管理”以一条模型详情串联身份→字段证据→发现账号→连接/路由→分组/有效售价→发布→审计，支持指定 scope/Key 的可用性和报价诊断。公开主入口统一模型广场；`/pricing` 为同一数据源价格视图；Cmd+K 使用同一模型检索及 ID 链接。`/monitor` 保留健康任务，渠道视图保留渠道语义。

## 4. 权限、Key 与首次引导

### 4.1 Scope

Personal 由认证用户确定，不接受客户端伪造 user_id；Workspace 是管理/授权汇总而非“第一个项目”；Project 必须是显式且归属于该 workspace 的项目。

前端以现有 `stores/app.ts` 的作用域子状态为唯一写者，`stores/consoleScope.ts` 与 `features/console/scope.ts` 只做代理。保留已有 generation、分页、会话清理。删除所有 activeWorkspace/activeProject 首项回退。首次无偏好进入 Personal；旧 personal 记录优先；失效/混合作用域阻断并给修复入口。URL 显式 scope 必须验证，不能污染另一页面。

“全部项目”只能是 Workspace 汇总；无汇总接口时要求选择具体项目。scopes 必须消费完整分页或按 ID 验证当前项，不能把第 51 项误判不存在。API 操作开始时冻结 scope，不能由发请求时的 window.location 将旧表单重写到新 workspace。所有异步结果按 user/scope/Key/version 校验，旧结果不覆盖新选择。

### 4.2 Key

Personal 创建按钮只签发个人 Key；Project 只签发本项目 Key，移除决定资源类型的复选框；Workspace 要求明确选择。个人默认分组由服务端显式配置，不取列表首项。没有可用路由/余额时给对应诊断，不借用 Default 项目授权/预算。

请求 actions 与调用者可委派、scope、Key 类型允许 actions 求交集；空交集直接阻断，不回退默认。模型规则显式区分 inherit/allow_list/deny_all；unknown 不等于无限制。项目表单只展示后端实际支持的安全与额度字段；不支持项禁用并解释，禁止静默丢弃或创建后再补限制。

列表增加真实生命周期与过期合同，使用服务端求值，不以 mock 虚构 state 过滤。诊断读取与执行资格区分；过期 Key 不可执行但不必禁止诊断。一次性 secret 首响应丢失时明确提供撤销重建流程，禁止保存明文供重放或自动生成另一个幂等键。

### 4.3 Workspace admin 授权

在 Workspaces 下增加成员与项目 action 编辑器，不放开平台 `/admin/members`。返回 `{project_id, actions}` 对应关系；每次写入只替换指定项目，使用 grant_version CAS。既有旧接口的批量替换语义保留，但遇到异构项目 grant 时拒绝有损写回并提示新合同。后端验证项目归属和委派上限，禁止 platform actions。显示继承权限、直接授权、有效权限、操作者和版本。

### 4.4 Playground

保持项目级；Personal 无项目时显示选择/申请引导，不切 Default。运行必须满足用户 playground.run、operation action、Key owner/act_as、有效生命周期、KeyPolicy、项目目录、有效销售报价及资金条件。服务端执行再校验。

切 Key 后重算模型候选；目录失败不得用公共目录继续运行。Key 报价 404 不得去 Key 重试。确认绑定 scope/Key/model/protocol/payer/payload 指纹；加载中、失败、无价、缺维度、资金阻断或上下文变化时不允许确认执行。Compare 全部侧都具有可信上限且同币种才显示总上限；不混币、不将已知一侧称总上限。金额使用既有精确十进制合同。

Replay 先解析源请求真实模型/协议，再报价，不能按当前表单残留模型估价。运行恢复标识按 user/scope 持久保留到确定终态；切 scope/卸载仅改变展示，不把未知结算当未执行，不自动生成新执行。

权限状态为 loading/allowed/denied/unavailable。401 重新认证；403 明确拒绝；404 资源不可见/不存在；503/网络/缺字段为未知并允许重试。任何异常都不能默认 true；BYOK 同样适用。

### 4.5 引导文案

* 首次个人空间：“你正在个人空间。创建个人 Key 后，可使用账户可用额度调用已开放的模型。项目资源需要项目授权。”
* 无项目权限：“你已加入 Default 工作空间，尚未获得项目授权。个人 Key 仍可独立使用。”
* Personal 打开 Playground：“Playground 使用项目权限和项目资源。请选择已授权项目，或向工作空间管理员申请。”
* 权限未知：“暂时无法确认此操作的权限，请重试。当前没有执行操作。”

没有申请后端时提供可复制的项目/action 申请说明和管理员入口，不假造审批状态或自动发送消息。

## 5. 配置与运维

部署配置 env > YAML > registry default，DB 不可覆盖连接/主密钥等部署边界。运行时配置仅显式 DB override > env > YAML > registry default。secret 使用引用和用途明确的密文；GET 不回显。空 secret 更新保持原值，删除/恢复继承用显式操作。

Effective API 返回 key、effective_value、source、override_state、default_value/default_version、setting_version/applied_version、restart_required、validation_state、blocked_by、修改审计；secret 只返回 configured/key_id/source。公开配置只投影白名单。

reset 删除 override，恢复继承；不能写入当前默认值冒充 reset。SSO/OAuth 成组原子 reset，避免 client ID 与 secret 混源。保留既有 OmittedSettingKeys/UpdateSettingsOmitting，补完整 schema 与遗漏检测。默认余额0、普通用户并发5；simple 安装管理员并发30保留。新安装目录自动刷新和公开广场默认 false，迁移保留现网已生效值并标 migration_snapshot。日志新安装 JSON，保留已有显式设置。

Turnstile 的 required 是安全下限，allowed 是能力上限，不能当同一 enabled；WebAuthn/Ops 同样显示约束和生效原因。已有 AutomaticEnv 继续使用，补显式环境变量合同和部署透传。

DB 无键与读取失败必须区分；故障不能静默回退另一存储。持久化密文解密失败不能当明文；连接测试请求的明文与持久化值分开处理。图片配置失败缓存短暂重试（建议1秒），成功配置本地即时失效并跨实例版本/最长30秒重检；安全/计费关键值不依赖30秒窗口。

引入独立集成凭证加密密钥与版本/key ID，TOTP 密钥继续服务 TOTP。迁移明确旧格式，逐项解密、重加密、读回验证；失败保留原值并隔离。共享图片/备份凭证保存引用，不复制秘密。备份档案加密与S3凭证加密是两种用途。

复用备份 leader lock、超时与更新 manifest/hash 校验。生产启用迁移前必须具备远端备份、校验、隔离恢复和真实定时任务成功证据；本地一次手工备份不能替代。发布/安装/在线及离线更新消费同一兼容清单；稳定 release 资产不覆盖。数据库 rollback floor 与安全语义 floor 分开；禁止破坏性 down migration。

| 级别 | 合并对象 | 权威选择与风险 |
| --- | --- | --- |
| P0 | Scope 多写者/URL隐式改写 | app scope唯一写者，操作捕获scope；保留分页和会话generation |
| P0 | 个人/项目 Key 混签、权限未知放行 | 一个签发应用边界、显式kind；保留legacy物理归属 |

## 10. 上线、回滚、观测与遗留风险

顺序：备份恢复证据→加法DB→兼容后端→前端→候选回填/shadow→按明确scope切读→确认唯一写者→旧实现退役。前端先于必需后端字段上线不可接受。关闭UI开关不等于撤销数据迁移。

观测：scope自动改写次数应为0；个人Key创建成功率、拒绝reason；unknown权限次数；grant CAS冲突；Key报价与执行指纹不匹配；reference进入执行次数应为0；provider歧义；缺/冲突价格；shadow差异；重复扣费应为0；配置应用版本差；密文解码失败；最近成功备份年龄、恢复耗时、发布校验失败。

安全/账单/provider异常单次即阻断切换并告警；可用性/性能按基线告警。日志不记录原始Key、tokens、完整提示内容、密文或跨租户信息。指标避免逐用户/Key/model的无限标签维度。

schema可启动floor不等于safe rollback floor。发生新密文/新策略/新报价语义写入后，仅回退到已验证可解释这些数据的构建；不得任意退回v0.3.3。正常回滚不恢复旧DB、不删新增表、不改旧账。在途请求按已冻结引擎完成；灾备恢复需隔离写入与对账。

运营待办由任务owner执行而非留产品决策：准备测试余额和既有平台测试账号；确认个人默认分组/路由；记录现网effective配置；远端备份与恢复演练；提供生产shadow时段。若环境未提供，不伪造完成状态，也不自动修改生产或外发消息。
