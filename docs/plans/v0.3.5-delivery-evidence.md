## 1. 本次实现的边界

| Key / grants | 项目凭证显式签发，真实生命周期及过期字段，空 action 交集阻断；模型规则统一写入 model_access_rules；成员授权按项目 CAS | project_key_policies 继续承载 action、owner、member-bound；历史冲突模型规则取交集并暴露 legacy_intersection，不能自动扩大权限 |
| Workspace admin | Workspaces 与原成员页复用逐项目授权组件；后端返回 project_grants 与 delegable_actions；冲突后重新读取并要求复核 | Workspace admin 已有非平台权限继承保持；平台管理页仍保留平台权限边界 |
| Playground / 任务 / BYOK | 项目 Key、真实权限、模型规则和生命周期共同限制操作；未知或读取失败关闭操作；Playground 报价绑定 Key 与请求上下文；任务页去掉伪造 Key state；BYOK 使用对应 workspace/project access | Playground 仍是项目产品；BYOK 原有 Workspace 聚合管理语义继续由同一个 Identity evaluator 决定 |
| 模型目录 | 复用注册表获取与相同模型投影；字段来源、发布时间/路由/价格分别表达；provider 明确，同名歧义拒绝；公开视角 requires_scope | v1/v1beta 形状和协议继续保留，适配层不是另一套模型事实写入口；参考候选不自动成为可调用模型 |
| 销售价格 | group/channel 是运营编辑权威；统一销售解析、价格上下文与 exact binding；报价、路由和执行使用同一请求局部价格快照 | exact_price_versions 不成为第二个任意编辑价格后台；已有历史计算与舍入记录保留；reference/cost/settlement 各自独立 |

| 设置 | registry defaults、effective/source 诊断、显式成组 reset 与版本 CAS；未修改的 GET→PUT 保留继承；秘密只显示配置状态 | 部署 env/YAML 与显式运行时 DB override 职责保留；安全 required/allowed 与 enabled 不是同一字段 |
| 发布 / 密钥 | 版本 0.3.5，兼容清单单一输入；安装/更新验证单调回滚下限；独立集成凭证加密 key 与旧格式读兼容 | 不强制批量重加密现网秘密，不重算账单，不覆盖已发布 release 资产 |

## 2. 从原问题扩展发现并修复的问题

1. **扁平授权的二次入口。** 原成员页仍把 project_ids × actions 作为可编辑集合，且冲突后可自动重试旧草稿。改为共用逐项目编辑器；后端旧接口遇到异构直接授权拒绝有损写回。
2. **任务页/BYOK 的错误状态放行。** 和 Keys/Playground 同类的非 403 错误、旧 Key 字段及作用域混用一并收敛；Workspace BYOK 使用真实聚合 access，不擅自改成仅项目能力。
3. **报价之后配置刷新。** 路由确定价格版本到真正 RequestPlan 捕获之间，可能发生价格、分组、个人倍率刷新。新增请求局部只读价格 bundle，冻结注册表、销售价格源、渠道快照、Key 分组、payer 倍率和时间锚点；接纳前比较版本，实际计费复用同一 bundle。该步骤不提前 Claim、不预占预算、不创建执行计划。
4. **exact 与 legacy 双收费口径。** 已激活 exact 销售价与运营有效销售形状不一致时拒绝报价，避免用一种公式报价再由另一种公式实收。
5. **连接管理的写入绕过。** 模型选择专用 SQL、批量账号更新及批量 credential 更新原先可绕过普通账号编辑守卫。现统一行锁检查和原子拒绝；409 含受影响账号 ID，前端提供连接管理入口。
6. **运行时订阅观察使连接消失。** plan_type 观察不得伪装成 v2 配置写者；专用事务标记只接受同一账号的单字段观察。真实值变化使旧连接验证失效、version 增加并发事件，同时保留连接可见；混合字段修改仍走原隔离守卫。
7. **配置故障与密文被误认缺省。** DB 缺键、DB 不可用、损坏密文和显式连接测试明文分开处理；图片配置失败短暂重试，成功设置主动失效；Ops 没有可信快照时关闭操作，旧可信快照的 stale 状态可诊断。
8. **公开目录的隐性承诺。** 移除来源冒充、缺字段猜路由、把 pi 参考价当主价，以及首页“任意模型均可调用”的示例；异步鉴权变化后丢弃旧目录结果。
9. **在线回滚下限不一致。** 在线指定版本回滚与本地回滚必须共同采用数据库、编译合同和发布清单的最高下限；数据库读取失败不得跳过下限校验。
10. **切作用域丢失一次性 Key。** Keys 页保持同主体的在途签发结果，捕获原作用域并在 secret 弹窗标注；多结果按内存队列展示，切主体/会话销毁全部 secret，不保存到浏览器持久存储。
11. **比较页绕过统一身份解析。** 旧名称链接必须经过完整分页和 provider 歧义检查，不能按当前列表第一项猜模型；详情 canonical 使用稳定模型 ID。
12. **安装与退役文档失真。** 统一兼容清单与 installer 生成常量，保持已验证回滚下限单调；onboarding 路由仍注册，退役清单修正为兼容 wrapper，未伪称已移除。

## 3. 迁移与回滚

| 迁移 | 数据影响 | 可重复与回滚策略 |
| --- | --- | --- |
| 339_price_book_bindings | 为不可变销售版本增加带时效和审计的激活绑定；保留旧价格记录 | 发布事务原子关闭旧绑定并激活新绑定；同一操作重试幂等；历史时刻仍能找到原价，失效价不能复活 |
| 340_configuration_authority_and_safe_rollback | 保留升级前缺省配置的有效行为与来源；收敛回滚约束 | 已有显式值/更高下限保留；无关字段与时间戳不改；重复执行结果稳定 |
| 341_connection_runtime_observation_fence | 更新连接隔离函数，增加仅供内部订阅观察使用的窄事务标记 | 不改历史迁移；账号/字段不匹配继续隔离；原已 dirty 连接不自动恢复；只清失效验证，不丢连接 |

迁移前须保留完整数据库及部署配置/密钥备份。新构建先于依赖新增合同的前端启用。新 schema 物理最低版本为 0.3.0，安全语义回滚最低版本为 **0.3.5**；更新入口使用二者最大值且不得降低数据库或已验证安装清单的更高下限。

“可回滚”是回到经过验证、理解本次语义的 v0.3.5 修订构建，不是把 v0.3.3 二进制指向迁移后的数据库。正常回滚保留加法表和历史记录；不执行 destructive down。灾备恢复与正常应用回滚分别演练。

重点反例：零 project_grants 的新用户不能借目录/个人 Key 获得项目权；pi-only、缺价、旧 price_version 在 admission 之前拒绝；Key 过期/撤权/切作用域关闭操作；同名跨 provider 价格不能互用；授权/配置 CAS 冲突不能自动重放；旧密文错误不能当明文；批量写必须全部成功或全部拒绝。

Playground 集成使用真实 HTTP handler、PostgreSQL/Redis、admission、预算和结算服务，但目录证据与上游响应使用确定性 fixture。它验证零调用/零预占/零扣费和本地流水，不是供应商真实付费调用。

## 5. 生产启用条件及剩余环境验证

本 PR 不自动合并、创建 tag、发布 GitHub release 或部署生产。以下由发布负责人按顺序完成，决策已确定，不再让工程执行者自行选择：

1. **备份门禁**：取得远端定时备份成功证据及异机恢复结果；检查数据库与旧/新加密 key 一起可恢复。近期一次本机备份不能代替此项。
2. **配置快照**：导出脱敏 effective/source、关键 feature flag、个人默认路由/分组、回滚下限；新装 false/JSON 与升级 migration_snapshot 必须分别核对。
3. **迁移与后端先行**：在隔离副本重放 339–341，验证旧账与生效配置，再滚动后端、最后前端；工作空间/Key/价格错误单次越权或串价即暂停。
4. **现网 shadow 与性能**：对实际运营组、账号目录、长上下文与分时价格采样比较旧投影和新解析；未知差异为零才扩大流量。真实生产 p95 目标相对基线劣化不超过 10%，不能靠放松授权换取性能。
5. **平台真机**：用授权测试账号验证 WorkBuddy、Kilo、OpenCode Zen 及现有协议；验收 OAuth 刷新、真实模型发现、免费/付费隔离和一次性 Key secret。无真实供应商凭证时不声称此项已完成。
6. **逐项激活**：运营价格编辑仍走既有 channel/group 命令；新 exact binding 必须与销售合同一致。新 secret key 按部署单独注入，逐项轮转并读回核验；不静默批量重加密。

观测优先复用现有错误 reason、请求日志、审计/outbox 和已具备的指标。方案中的全部监控指标名称不是本 PR 已部署的 Prometheus dashboard；上线负责人需在实际监控系统配置零越权、零参考价执行、零重复扣费、来源异常、配置应用版本差、备份年龄和兼容性校验告警，避免高基数用户/Key 标签。

## 6. 保留而非删除的内容

v1/v1beta 兼容入口、个人/项目凭证合同、历史 Default 物理域、项目 action 策略表、已有运营价格写入界面、账号调度投影、不同财务价格类型及安装入口都保留。它们通过共同求值或窄兼容层约束，不因“文件看起来重复”强行删除。

报价确认使用服务端版本和上下文检查；60 秒确认窗口由当前 UI 合同执行。本次未新增可供第三方长期保存的签名报价凭证，也不把该窗口描述为独立密码学授权。历史计费不重算。

本次不新增 AIStudio2API、Gemini Web2API、ChatGPT Web 插件，不自动赠金，不引入消息审批系统，不做全站视觉重写。结构性删除仅在消费者和回滚依赖均清空之后另行进行。
