## 上游账号凭据

先停止所有旧实例及后台写入者，保存升级前的数据库备份，并单独保管现用的 64 位十六进制 TOTP_ENCRYPTION_KEY。所有实例必须使用相同的持久密钥。已有密文的部署须继续使用原密钥。release 模式缺少固定密钥时启动失败。

迁移 321 登记存量账号，包括软删除账号，并拒绝写入明文秘密。应用在接流量前每批锁定最多 64 个账号，在同一事务中写入 AES-GCM 密文、绑定账号与工作空间的引用并移除队列项。重启会继续处理剩余项。可通过 SELECT count(*) FROM account_secret_backfill 检查进度。Ollama 的同 Key 用量分组使用摘要。

升级后的数据库逻辑备份须和主密钥分开保管。升级前的备份、既有 WAL 和显式管理员凭据导出仍含秘密。回退到旧写入器需要停机恢复升级前的数据库快照和对应密钥，先处理快照之后的业务数据。

## JWT 签名与轮换

release 会检查配置和数据库中实际使用的 JWT 签名密钥。公开样例、短密钥及简单重复串均会阻止启动。首次启动可以留空，由数据库引导逻辑生成随机值。已有部署只改配置仍会沿用库中密钥。

轮换时停止所有进程，配置新生成的至少 32 字节 JWT_SECRET，在一个实例设置 JWT_ROTATE=true 并启动。成功后移除轮换开关，再使用相同配置启动全部副本。禁止重新使用旧密钥。旧 JWT 的签名立即失效。刷新令牌在 Redis 中按签名密钥计算 HMAC 索引，本次升级前签发的刷新令牌及每次轮换前的刷新令牌都需重新登录。恢复旧数据库快照或旧签名密钥可能重新激活旧会话，恢复后应再次轮换。
